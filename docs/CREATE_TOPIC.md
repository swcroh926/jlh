# Create_Topic — 주제 생성·검사·재평가

2026년 11월 18일. 작업 브랜치의 로컬 기능이며 공개 배포하지 않았습니다.

## 무엇이 달라졌나요?

이전에는 추천 후보가 부족하면 입력을 수정하라는 안내만 나왔습니다. 이제 기존 평가·확정 관심사·수행 조건·관련 수상작 제목을 참고해 새 주제 최대10개를 제안하고 제목 중복 검사와 같은5항목 평가를 이어서 실행합니다. 사용자가 원본20개+생성10개를 모두 비교하는 **최대30개**를 선택했습니다. 명세 원문의 내부25개는 변경하지 않고 사용자 결정을 이 문서에 기록합니다.

- 화면: 제목·쉬운 설명·질문·원본 연결·생성 방법·보완 항목·실험 개요·확인 조건·실제 인용 출처를 표시합니다.
- Python: 저장된 최신 평가와 관심사/검사 버전을 확인하고 생성→검사→재평가를 진행합니다. 브라우저가 보낸 점수나 임의 출처를 신뢰하지 않습니다.
- AI: 기존 OpenAI 어댑터로 상위 평가5개(적으면 실제 수), 원본 관심사·수행 조건·중복 근거를 전달합니다. 실제 웹 검색이나 모델 파인튜닝은 아닙니다.
- 저장소: .local/generation.sqlite3에 시도·초안·부분 실패·완료 이력, 평가 DB에 재현 입력을 저장합니다. 브라우저는 현재 목록·이전 목록·평가를 프로젝트 이력에 보존합니다.

원본 주제와 관심사 근거/분모는 그대로입니다. 생성 주제는 별도 목록으로 관리하고, 재평가는 원본+생성 최대30개를 함께 처리합니다. 추가 생성은 현재 생성 목록을 새 목록으로 교체하며 이전 목록은 이력에 보존합니다. 생성 목록을 무한히 누적하지 않습니다.

## 자동 실행과 비용

기본은 자동 생성 꺼짐입니다. ‘평가 후 추천 후보가 부족하면 자동으로 한 차례 생성·재평가’에 비용 동의한 경우, 현재 조건의 원본 평가에서 추천3개 미만이면 자동 실행합니다. 서버도 조건별 자동 시도를 한 번만 허용합니다. 실패해도 자동으로 재귀 반복하지 않습니다. 이후 추가 생성은 사용자가 버튼을 눌러 실행합니다.

한 번의 흐름에서 생성 요청1회, 부족/중복 시 보완 요청 최대1회, 최종 재평가1회를 수행할 수 있습니다. 제목 중복 검사는 API 없이 진행하고 의미 검사는 이 흐름에서 자동 실행하지 않습니다. 실제 유료 호출 전 비용 안내를 표시합니다. START_LOCAL.bat의 무료 실행에서는 실제 AI 평가/생성이 활성화되지 않습니다.

동일한 정규화 제목, 잘못된 원본 연결·평가 항목·제공되지 않은 출처 ID는 제외합니다. 수상작과 제목이 같거나 검사 미완료인 생성안은 보완 대상으로 돌립니다. 그래도10개를 채우지 못하면 부분 목록과 이유를 표시합니다. 원본의 이전 중복 승인을 새 검사에 자동 계승하지 않습니다.

**한계:** 현재는 제목 기반 검사와 모델의 보완 지침을 사용합니다. 표현이 다른 실질적 중복·위험한 방법의 재등장 방지·제안 품질을 완벽히 검증한 것은 아닙니다. 실제 의미 검색·보고서 정보·교사 사례 보정이 필요합니다. 높은 점수는 수상 확률이 아니고, 실행 가능 상태는 현장 검증을 대체하지 않습니다.

## 직접 확인하기

1. 최신 개발 ZIP으로 업데이트하고 .local 폴더를 유지합니다.
2. START_AI_LOCAL.bat에서 기존 절차대로 비용 동의 후 키를 숨김 입력합니다.
3. 원본 확정 → 관심사 확정 → 중복 검사 → 전체 아이디어 평가를 마칩니다.
4. 후보 화면 아래 ‘새 탐구 주제 제안’에서 ‘새 주제10개 생성·검사·재평가’를 누르고 비용 안내를 확인합니다.
5. 새 주제의 질문·설명·원본 연결과, 위 평가 영역의 합산 후보/추천 상태를 확인합니다. 생성안의 수상작 비교는 중복 검사 영역에서 확인합니다.
6. 자동 실행을 원하면 평가 전에 자동 생성 비용 동의 체크박스를 켭니다. 원본 평가에서 추천3개 미만일 때 한 차례 실행합니다.
7. 재평가 실패 시 초안과 실패 단계를 확인하고, 조건을 보완해 검사/평가 또는 수동 추가 생성을 진행합니다. 기존 노트와 이전 평가는 이력에 남습니다.

평가 결과가 없거나, 과거 기준·만료24시간·변경된 데이터/검사 근거이면 생성 전에 재평가를 요구합니다. 서버 프로세스가 요청 도중 강제 종료되면 진행 중 기록이 남을 수 있으며, 중단 작업 재개 기능은 아직 없습니다. 공개 인증 서버와 기기 간 동기화는 이번 범위가 아닙니다.
