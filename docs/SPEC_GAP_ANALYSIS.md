# 기능명세 비교 및 순차 개발 계획

기준: 사용자 제공 `FUNCTIONAL_SPEC_v1.1.md` (v1.0 본문 + v1.1 중복 위험 검사 추가).
확인일: 2026년 11월 18일 (한국 시간).
작업 브랜치: `feature/spec-v11-inputs`.

**기존 기능은 재사용하며, 이번 범위는 로컬 실행·검증입니다. main에 병합하거나 공개 배포하지 않습니다.**

## 사용자 결정과 해석

- 원문은 1~20개와 15개 제한을 함께 적고 있습니다. 사용자가 **최대 20개**로 명시해 입력·서버 검증을 이에 맞춥니다. 원문 파일은 수정하지 않습니다.
- 원본 20개 + 생성 10개는 30개입니다. 원문의 ‘내부 최대 25개 비교’와 범위가 충돌하므로, 생성 단계에서 보존·평가 범위와 비교 후보 선택 규칙을 확정해야 합니다. 현재 원본을 임의로 15개로 줄이지 않습니다.
- v1.1 중복 위험 검사와 보류 규칙은 v1.0의 단순 점수 통과보다 우선해 향후 추천에 반영합니다.
- 기존4항목 평균/70점 초과를 새5항목 가중 평가/80점 이상으로 개편했습니다. 과거 기록은 보존하며 재평가를 요구합니다.
- 무료 모델/호스팅 논의는 보류 상태로 유지합니다. 이 작업에서 유료 API 호출·Render 서비스 생성·Gemini 전환은 하지 않습니다.

## 순차 작업 목록

1. **완료: 입력 기반 정비** — 학생/선생님 조건, 최대20개, 원본 ID, 파일 추출·확인, 기존 상태 보존·재검토 표시. 아래 확인 방법 참조.
2. **로컬 구현 완료: Find_Interest** — 원본 주제만 사용한 5영역 분류·근거 ID별 수/비율·교사 수정/확정·관심도 무효화. AI 모델 응답은 모의 검증이며 직접 분류/서버 계산/저장/실제 HTTP는 검증. [사용 및 검증](FIND_INTEREST.md).
3. **로컬 구현: Check_Duplicate** — 상태·실제 출처·제목 표현 비교·검사 미완료·교사 검토·연구 묶음/버전·고득점 보류 연결. 의미 검색은 모의 벡터로 검증했으며 실제 품질과 판정 보정은 남습니다. 생성 주제 검사 계약은 준비했지만 실제 생성 루프는 미구현입니다. [사용 및 검증](CHECK_DUPLICATE.md).
4. **로컬 구현: Eval_Topic 개편** — 5항목/가중치/80점 이상/실행 상태·중복 위험 보류·이전 평가 보존. [계약과 직접 테스트](EVAL_TOPIC.md).
5. **다음: Create_Topic** — 10개 생성, 원본관심사 고정, 후보 상한 충돌 해결, 자동1회·수동추가·재검사·재평가.
6. **최종 선택 + Set_Exp** — 수동 주제도 검사·조건 검토, 주제별 계획·비용·일정·초안·교사 확정·버전 보존.
7. **서버 프로젝트 저장·종합 검증** — 각 단계의 ID/버전 계약에 맞춰 저장을 점진적으로 추가하고 최종 재시작/회귀/품질 비교 검증. 현재의 브라우저 저장만으로 완료 처리하지 않음.

## 첫 작업 직접 확인

기존 체크아웃에서 작업 브랜치를 사용합니다. 별도 worktree는 만들지 않습니다.

```sh
python3 -m backend.server --port 8012
```

서버와 같은 컴퓨터의 브라우저에서 포트 8012를 엽니다. 사용자 PC의 localhost와 Codex 컴퓨터의 localhost는 서로 다릅니다. 공개 주소에는 이번 변경이 배포되지 않습니다. Windows 로컬 실행 명령은 `py -3 -m backend.server --port 8012`입니다.

1. 빈 학생별 예산에서 30만 원 적용, 0 입력 시 0원 적용을 확인합니다.
2. 이름·학년·지역·장소를 입력하고 주제를 20개/21개 또는 동일하게 입력해 봅니다.
3. TXT·DOCX·HWPX 파일을 불러오면 먼저 미리보기를 보여줍니다. 추가/교체/취소를 선택하기 전에는 기존 입력을 바꾸지 않습니다.
4. ‘주제 목록 확인하기’ → 내용을 확인하고 ‘이 목록으로 확정하기’를 누릅니다. 기존 후보·검색·평가 화면으로 연결됩니다.
5. 선생님 기본값을 수정해도 현재 프로젝트는 유지됩니다. 새 프로젝트에는 새 기본값을 적용합니다. 이전 프로젝트는 ‘이 브라우저의 프로젝트 보관함’에서 복원합니다.
6. 실험 기록 작성 후 조건을 변경하면 기록은 남고 이전 계획/평가를 재검토하라고 표시합니다.

DOCX·HWPX는 합성 문서로 실제 로컬 HTTP 추출을 검증했습니다. 사용자가 실제로 사용하는 표/레이아웃이 복잡한 파일은 추가 샘플로 품질을 확인해야 합니다. HWP 변환기는 이 환경에 설치하지 않았으며, 가짜 변환기 응답으로 성공/실패 분기와 미설치 안내만 검증했습니다.

## 테스트

```sh
npm test
python3 -m unittest discover -s backend/tests -v
```

Playwright/Chromium이 있는 환경에서는 서버 실행 후:

```sh
node tests/browser/phase1.mjs
```

브라우저 테스트는 Python 테스트의 `archive`, `DOC`, `HWPX` 헬퍼로 `.local/phase1-fixtures/`에 합성 문서를 자동 생성합니다. 테스트는 실제 파일 추출 엔드포인트와 기존 검색을 사용합니다. 평가 요청은 테스트 응답으로 대체하며 실제 유료 API를 호출하지 않습니다.

## 남아 있는 제약

- 기본값/프로젝트 보관/원본 주제는 아직 현재 브라우저에 저장됩니다. 서버 저장·다른 기기 동기화·계정 권한은 별도 단계입니다.
- 서버 문서 추출은 로컬 실행용 경로에만 추가했습니다. Render 공개 앱으로 확장/배포하지 않았습니다.
- 현재5항목 가중 평가/80점 이상으로 개편했으며, 과거4항목 기록은 재평가 대상으로 보존합니다.
- 관심사와 중복 검사는 로컬 구현했습니다. 중복 검사는 현재 제목 정보에 근거하며, 보고서 방법 비교·실제 모델 품질 보정은 남아 있습니다. 5항목 평가의 로컬 흐름은 구현했고 실제 모델 품질 검증은 남아 있습니다. 주제 생성·주제별 실험 계획은 아직 완료 범위가 아닙니다.

## 2단계 관심사 기능 확인

원본 주제를 확정한 뒤 후보 화면의 관심사 패널에서 직접 분류 또는 AI 분석을 선택합니다. AI 분석은 API 사용 확인 후에만 실행합니다. 직접 분류·확정에는 API 키가 필요하지 않습니다. 원본 주제와 연결한 관심사 확정 및 유효한 중복 검사를 마치고 API 키가 있을 때 실제 평가가 활성화됩니다. 수정 중에는 다시 비활성화합니다. 원본이 바뀌면 이전 관심사/평가는 보존하며 재확정을 요구합니다. 자세한 계약·계산·저장·재현 가능한 모의 모델 테스트는 [FIND_INTEREST.md](FIND_INTEREST.md)에 있습니다.

## 3단계 중복 검사 확인과 검증 상태

무료 START_LOCAL.bat로 후보 화면의 ‘제목 기준 검사 (무료)’를 누릅니다. 보유 제목인 ‘균근과의공생이식물의성장에미치는영향’을 넣으면 제목 일치 위험과 실제 출처를 확인할 수 있습니다. 위험은 원문을 확인한 선생님이 근거를 적어 승인하기 전까지 추천에서 보류됩니다. 검사/승인·출처 묶음은 SQLite에 버전으로 저장하며, 질문·방법·자료·묶음이 달라지면 이전 기록을 남기고 재검사를 요구합니다.

현재 Python 81개·Node 27개 자동 검사, 입력/관심사/중복 단계의 로컬 브라우저 검증을 통과했습니다. 제목 검색·HTTP·SQLite는 실제 코드와 자료를 사용했습니다. 평가 응답은 모의 모델, 의미 검색은 테스트 벡터 및 실패 주입으로 검증했습니다. 이번 단계의 실제 유료 API 호출, Windows 실사용 검증, 공개 배포는 하지 않았습니다. 자세한 절차와 제한은 [CHECK_DUPLICATE.md](CHECK_DUPLICATE.md)를 참고하세요.
