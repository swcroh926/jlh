# 개발 중인 앱을 내 윈도우 PC에서 확인하기

## 공개 사이트와 개발본의 차이

공개 사이트 `https://swcroh926.github.io/jlh/`는 main 브랜치에 배포된 버전입니다. 현재 명세 작업은 `feature/spec-v11-inputs` 브랜치에서 진행하므로 공개 사이트에 바로 나타나지 않습니다.

내 PC에서 최신 개발 코드를 실행하면 학생 입력·문서 가져오기·실제 자료 제목 검색·중복 위험 검사와 교사 검토·직접 관심사 분류·수정·저장 등을 확인할 수 있습니다. 기본 실행 파일 START_LOCAL.bat는 API 키를 전달하지 않아 **유료 AI 호출을 하지 않습니다.**

## 1. 최신 개발본 받기

다음 ZIP을 다운로드합니다.

https://github.com/swcroh926/jlh/archive/refs/heads/feature/spec-v11-inputs.zip

ZIP을 우클릭하여 ‘모두 압축 풀기’를 선택합니다. 압축 내부에서 바로 실행하지 않습니다. 압축을 푼 폴더 안에 `START_LOCAL.bat`, `app.js`, `backend` 폴더가 있는지 확인합니다.

## 2. Python 확인

수집 도구를 실행할 때 설치한 Python 3.10 이상을 그대로 사용할 수 있습니다. Node.js·Git·개발 도구 설치는 이 테스트에 필요하지 않습니다.

Python이 없다는 안내가 나오면 https://www.python.org/downloads/windows/ 에서 설치하세요. 설치 시 ‘Add python.exe to PATH’를 선택합니다.

## 3. 실행

**START_LOCAL.bat를 두 번 클릭**합니다.

- 검은 실행 창을 열어둡니다.
- 준비되면 기본 브라우저를 자동으로 엽니다.
- 브라우저가 열리지 않으면 주소창에 `http://127.0.0.1:8012`를 입력합니다.
- 이 주소는 지금 서버를 실행한 PC에서만 열립니다. 휴대폰이나 다른 컴퓨터의 같은 주소에서는 열리지 않습니다.
- 실행 창을 닫으면 앱 서버도 종료됩니다. 다시 START_LOCAL.bat를 실행하면 됩니다.

이 배치 파일은 자신의 실행 프로세스에서만 LLM_API_KEY/OPENAI_API_KEY를 비우고, 결과 폴더를 프로젝트의 `.local`로 지정합니다. 다른 프로그램에 저장된 키를 삭제하거나 전역 환경 변수를 수정하지 않습니다.

## 4. 지금 확인할 수 있는 것

1. 이름/별명·학년·지역을 입력합니다.
2. 예산을 비우면 30만 원, 0을 입력하면 실제 0원으로 적용되는지 확인합니다.
3. 원본 주제 1~20개를 입력하거나 TXT·DOCX·HWPX 파일을 불러옵니다. 추출 내용을 수정한 뒤 추가/교체하고, 목록을 확인·확정합니다.
4. 관심사 패널에서 **직접 관심사 작성·수정 → 관심사 추가**를 누릅니다.
5. 구체적 관심사 이름·분류 이유·영역·근거 원본을 선택하고 ‘관심사 분류 확정’을 누릅니다. 분류가 어렵다면 관심사 없이 불확실성 이유를 적어 확정할 수도 있습니다.
6. 비율과 근거 주제, 미분류 항목을 확인합니다. 새로고침해도 유지되는지 봅니다.
7. 관심사를 수정하면 이전 평가가 재평가 대상으로 바뀌는지 확인합니다.
8. ‘제목 기준 검사 (무료)’로 원본 주제의 중복 위험·참고 출처·검토 승인/보류를 확인합니다. 자세한 예시는 아래8절에 있습니다.
9. 유사 제목 검색, 기존 예시 후보 선택·공통 실험 계획·기록 화면도 확인할 수 있습니다. 예시 점수를 실제 AI 평가로 해석하지 않습니다.

이 실행 방식에서는 **AI 관심사 분석과 실제 AI 평가 버튼이 비활성화되는 것이 정상**입니다. 실제 모델 답변을 테스트하려면 별도로 모델/API를 설정해야 합니다. Codex에 저장한 키는 개인 PC로 자동 전달되지 않습니다. 키를 코드나 화면의 접근 코드 칸에 넣지 마세요.

HWP는 변환 도구가 없으면 HWPX·DOCX·TXT 변환 방법을 안내합니다. 스캔 문서 OCR, 5항목 가중 평가, 자동 주제 생성, 주제별 AI 실험 설계는 아직 완료한 기능이 아닙니다. 중복 검사는 제목 수준이며 실험 방법·표절 판정이나 독창성 보장이 아닙니다.

## 5. 다음 개발본으로 업데이트하기

1. 이전 앱 실행 창을 닫습니다.
2. 위 ZIP 링크에서 최신 코드를 다시 받습니다. 브랜치 주소는 같아도 개발 커밋이 추가되면 내용이 달라집니다.
3. 기존 앱 폴더 전체를 백업한 뒤, 새 코드 파일만 기존 폴더에 덮어씁니다. **`.local` 폴더는 유지합니다.** 새 ZIP에는 `.local`이 없습니다.
4. START_LOCAL.bat를 실행하고 브라우저에서 Ctrl+F5로 새로고침합니다.

브라우저의 학생 정보/프로젝트는 같은 브라우저·같은 주소의 저장 공간에, 관심사 서버 버전은 `.local/interests.sqlite3`, 중복 검사/검토 버전은 `.local/duplicates.sqlite3`에 있습니다. 모두 보존해야 합니다. 새 폴더에 따로 실행한다면 이전 `.local`도 복사해 두세요. 브라우저 데이터를 지우거나 `localhost`와 `127.0.0.1`을 번갈아 사용하면 다른 저장 공간으로 보일 수 있어, 이 안내서는 **127.0.0.1:8012**로 통일합니다.

프로젝트 기록 화면의 JSON 내려받기도 별도 백업 수단입니다. 현재 JSON 파일을 다시 가져오는 복원 기능은 없으므로 원본 저장 공간을 지우지 마세요.

## 6. 문제가 생기면

- **연결할 수 없음:** 실행 창이 열려 있는지, 같은 PC의 127.0.0.1:8012인지 확인합니다.
- **포트 사용 중:** 이미 켜둔 앱 실행 창을 닫고 다시 실행합니다. 모르는 프로그램을 임의로 종료하지 마세요.
- **Python 없음:** 설치 후 새 실행 창으로 다시 시도합니다.
- **코드를 수정했는데 화면이 같음:** 브랜치 ZIP을 받았는지 확인하고 Ctrl+F5로 새로고침합니다.
- **관심사 버전 없음:** 새 폴더로 옮기며 `.local`을 빠뜨렸는지 확인합니다. 이전 폴더를 보존하거나 새 서버에서 관심사를 다시 확정합니다.

피드백은 ‘입력한 예시 → 누른 버튼 → 기대한 결과 → 실제 결과’와 화면 캡처를 보내주시면 됩니다. 학생 실명 대신 별명을 쓰고, API 키나 비밀 값은 캡처에서 제외하세요.

## 7. 실제 관심사 AI 분석을 테스트하려면 (OpenAI)

현재 연결된 제공자는 OpenAI이며 Gemini 무료 API는 아직 연결되지 않았습니다. 관심사 분석 코드는 이미 서버에 있고, 비용 없는 START_LOCAL.bat에서만 의도적으로 비활성화합니다.

1. 이전 START_LOCAL.bat 실행 창을 닫습니다. 포트 8012에서 무료 서버와 AI 서버를 동시에 실행할 수 없습니다.
2. 최신 개발 ZIP을 다시 받아 코드만 업데이트하고 `.local`은 유지합니다.
3. **START_AI_LOCAL.bat**를 두 번 클릭합니다.
4. 검은 창에서 비용 안내를 읽고 계속하려면 **YES**를 입력합니다. Enter만 누르면 취소합니다.
5. OpenAI API 키를 검은 창의 숨김 입력란에 붙여넣고 Enter를 누릅니다. 입력한 글자가 보이지 않는 것이 정상입니다. 이 키는 파일·코드·브라우저 저장소에 기록하지 않고 실행 중인 서버 프로세스에만 전달합니다.
6. 열린 브라우저에서 원본 주제 목록을 확정한 뒤 **AI 관심사 분석 (API 사용)**을 누릅니다. 별도의 비용 확인 창을 승인하면 실제 API 요청이 발생합니다.
7. AI 초안의 관심사·영역·근거 주제·불확실성을 확인하고 수정한 뒤 **관심사 분류 확정**을 누릅니다.
8. 키 연결이 준비되면 확정한 관심사로 실제 AI 평가도 실행할 수 있습니다. 현재 평가는 기존 4항목이고, 명세의 5항목 가중 평가는 아직 다음 작업입니다.

키 발급: https://platform.openai.com/api-keys

Codex에 저장한 HTTP 시크릿은 PC에 자동으로 내려받아지지 않습니다. 키를 다시 볼 수 없다면 같은 OpenAI 프로젝트에서 테스트용 키를 새로 발급해 사용할 수 있습니다. **이름이 비슷한 Gemini 키를 OpenAI 실행 파일에 넣으면 동작하지 않습니다.** 키를 채팅이나 캡처로 보내지 마세요.

이 실행 파일도 서버를 켜는 것만으로는 API 요청을 하지 않습니다. 실제 분석/평가 버튼을 눌렀을 때 호출하며 사용량에 따라 과금될 수 있습니다. 프로젝트에 결제·크레딧이 있어야 하고, ChatGPT나 Gemini 앱 구독과는 별도입니다. 관심사 분석은 동일 입력/모델/기준의 초안을 24시간 재사용하므로 다시 누를 때 새 유료 호출이 생기지 않을 수도 있습니다.

AI 설정 완료 표시와 키의 유효성은 다릅니다. 실제 분석에서 권한 오류가 나면 키의 프로젝트/유효성을, insufficient_quota 안내가 나면 결제·크레딧을 확인합니다. 오류 화면에 키를 붙여넣어 문제를 해결하려고 하지 마세요.

다시 비용 없는 화면 테스트로 돌아가려면 AI 실행 창을 닫고 **START_LOCAL.bat**를 실행합니다. 두 실행 방식은 같은 주소와 `.local`을 사용하므로 기록이 유지됩니다.

## 8. 새 기능: 기존 작품과 중복 위험 검사

이전에는 유사 제목 목록만 나왔지만 이제 주제별로 중복 위험·유사 연구 있음·현재 범위에서 미발견·검사 미완료를 표시합니다.

무료 START_LOCAL.bat에서 주제 목록을 확정한 뒤 **‘기존 작품과 중복 위험 확인 → 제목 기준 검사 (무료)’**를 누르세요. 실제 보유 제목인 ‘균근과의공생이식물의성장에미치는영향’을 그대로 입력하면 제목 일치 사례를 확인할 수 있습니다.

‘유사 연구·차이·보완 방향 펼치기’에서 원문을 확인하고, 차별성이 있으면 검토 근거를 적어 승인하거나 보류합니다. 위험 표시 자체는 남습니다. 같은 연구임을 원문으로 확인한 지역/전국 출처는 근거를 남겨 묶을 수 있습니다. 자료/질문/방법/묶음이 바뀌면 재검사하며, 이전 승인이 새 검사에 자동 적용되지는 않습니다.

의미 검사는 색인과 API 연결이 필요하고 비용이 발생할 수 있습니다. 의미 검사가 실패하면 미완료로 표시하며, 무료 제목 검사로 바꾸려면 제목 검사 버튼을 직접 누릅니다. 실제 평가 버튼은 관심사 확정과 유효한 검사를 모두 요구합니다. 상세 사용법과 한계는 [CHECK_DUPLICATE.md](CHECK_DUPLICATE.md)에 있습니다.
