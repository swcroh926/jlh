# Check_Duplicate — 주제 선정 전 중복 위험 검사

구현일: 2026년 11월 18일. 현재 작업 브랜치의 **로컬 기능**이며 공개 사이트에 배포하지 않았습니다.

## 사용자가 얻는 기능과 개발 흐름

이전에는 관련 제목 목록만 검색했습니다. 이제 원본·생성 주제별로 기존 작품을 비교하고 다음 상태를 표시합니다.

- **중복 위험**: 공백·기호·대소문자 등을 정규화했을 때 같은 제목이 기존 작품 또는 입력 주제 사이에 있습니다. 동일 연구나 표절이라는 판정은 아닙니다.
- **유사 연구 있음**: 관련 제목이나 의미 검색 후보가 있어 원문 검토가 필요합니다.
- **현재 자료에서 뚜렷한 유사 연구 미발견**: 명시한 검색 방식과 현재 보유 제목 범위에서 후보를 찾지 못했습니다. 독창성을 보장하지 않습니다.
- **검사 미완료**: 자료 오류·색인 누락·의미 검색 실패 등으로 선택한 검사를 완료하지 못했습니다. ‘관련 연구 없음’으로 바꾸지 않습니다.

전체 흐름은 입력 → 관심사 확정 → 중복 위험 검사 → 평가 → 주제 생성·재평가 → 실험 계획입니다. 이번 작업은 중복 검사와 기존 평가의 보류 연결까지이며 5항목 가중 평가 개편은 다음 단계입니다.

## 어떤 부분이 바뀌었나요?

| 부분 | 역할 |
| --- | --- |
| 화면 | 주제별 상태, 유사 연구 상위5건, 실제 원문 링크, 공통 제목 표현/확인할 차이, 보완 방향, 검토 승인·보류 |
| Python 서버 | 제목 정규화·검색 결과 조합·상태 계산·데이터/검사 버전 검증·평가 추천 보류 |
| AI 모델 | 의미 검사를 선택하면 기존 임베딩 API 사용. 비교 설명을 위한 별도 생성형 AI 호출은 없으며 제목에 없는 방법을 만들지 않음 |
| 저장소 | .local/duplicates.sqlite3에 검사·검토 버전 및 확인된 연구 묶음/변경 이력 저장. 브라우저에는 프로젝트와 연결된 결과·보완 입력·과거 결과 보존 |

## 직접 확인하기 — 무료 경로

1. 최신 개발 브랜치를 받아 기존 `.local`을 유지하고 START_LOCAL.bat를 실행합니다.
2. 학생 정보와 원본 주제를 입력하고 확인·확정합니다. 예를 들어 실제 보유 제목인 **‘균근과의공생이식물의성장에미치는영향’**을 입력할 수 있습니다.
3. 후보 화면의 ‘기존 작품과 중복 위험 확인’에서 **제목 기준 검사 (무료)**를 누릅니다. 이름·지역을 검색 API에 전송하지 않습니다.
4. 각 카드의 상태를 보고 ‘유사 연구·차이·보완 방향 펼치기’를 누릅니다. 제목과 출처·연도·원문 링크를 확인합니다.
5. 제목이 같아도 실질적인 차별성이 있다고 판단하려면 원문을 확인하고, **차별성 검토 근거**를 적어 ‘차별성 확인 후 승인’을 누릅니다. 위험 표시 자체는 남고 검토 보류만 해제됩니다.
6. ‘검토 보류’를 누르면 점수가 높아도 자동 추천에 포함하지 않습니다. ‘검사 미완료’는 승인할 수 없고 재검사가 먼저입니다.
7. 선택 항목인 탐구 질문·대상·접근 방법·측정 지표를 수정하면 이전 결과를 보존하면서 재검사를 요구합니다.

무료 실행에서도 검사·출처 묶음·검토와 저장 기능을 확인할 수 있습니다. 실제 AI 평가 버튼은 관심사 확정·유효한 검사·API 키가 있어야 활성화합니다. 기존 예시 후보 카드는 계속 예시로 표시하며 검사 상태를 함께 표시합니다.

## 제목 검사와 의미 검사의 차이

- **제목 기준 검사**: API 없이 수행하며 제목 표현만 비교합니다. 화면에 ‘의미 검색 미실행’을 명시합니다.
- **의미 검색 포함 검사**: 같은 데이터로 만든 완성된 색인과 API 연결이 있을 때 사용합니다. 사용자가 비용 확인을 승인해야 임베딩 요청을 합니다. 제목·제공한 질문/대상/방법/지표를 검색 문장에 포함합니다.
- 의미 검사를 선택했다가 실패하면 제목 검색으로 조용히 대체하지 않고 ‘검사 미완료’를 저장합니다. 필요하면 사용자가 명시적으로 무료 제목 검사를 다시 실행할 수 있습니다.
- Codex의 색인과 시크릿은 Windows로 자동 전달되지 않습니다. 색인이 없는 PC에서는 의미 검사 버튼이 비활성화됩니다. 색인 생성은 기존 `python -m backend.server --build-index` 기능이며 API 비용이 발생할 수 있습니다.

두 방식 모두 현재는 수상작 **제목**에 근거합니다. 원문 보고서가 없으므로 기존 작품의 실제 실험 방법·결과를 추정해 비교하지 않습니다. 추가로 입력한 방법은 보존·검색에 참고하되 ‘기존 방법과 다르다’는 사실로 만들어내지 않습니다.

## 판정 기준과 한계

- 제목은 NFKC·대소문자·공백/기호를 정리합니다. 키워드와 연속 글자 조각의 겹침으로 후보를 찾습니다.
- 제목이 일치하는 후보는 의미 검색 점수와 관계없이 포함합니다.
- 초깃값으로 제목 Dice 유사도 0.15 이상이면서 공통 글자 조각 2개 이상인 자료를 후보로 봅니다. 의미 검색 후보는 cosine 0.45 이상을 초기 검색 기준으로 사용합니다.
- 이 숫자는 중복 확률이 아닙니다. 화면에 백분율로 표시하지 않습니다. 실제 검색 품질은 선생님의 유사/비유사 사례로 보정해야 합니다.
- 매우 유사해 보이더라도 정규화 제목이 다른 경우에는 우선 ‘유사 연구 있음’으로 보수적으로 표시합니다. 같은 소재만으로 자동 고위험 판정하지 않습니다.
- 차별화 제안은 비교 조건·측정 지표·검증 질문을 구체화하라는 일반 안내입니다. 별도 AI가 실제 보고서를 읽고 만든 제안은 아닙니다.
- 검색 실패 때는 실패 원인을 보존하고, 실패 보고서를 새 추천 근거로 통과시키지 않습니다.

## 같은 연구의 지역·전국 출처 묶기

같은 제목이 여러 사이트에 있어도 자동으로 한 연구로 합치지 않습니다.

1. 검사에서 표시된 출처의 원문을 확인합니다.
2. ‘같은 연구임을 확인한 출처 묶기’를 펼칩니다.
3. 같은 연구라고 확인한 출처 2~10개를 선택하고 확인 근거를 씁니다.
4. 묶기 버튼을 누릅니다. 다음 검사에서 한 연구 항목 아래 원래 출처 링크들을 모두 보존합니다.
5. 판단이 바뀌면 이유를 적고 묶음을 해제할 수 있습니다.

묶음 변경은 데이터 해석 범위를 바꾸므로 기존 검사·승인은 재검토 대상입니다. 검토 근거 없는 자동 병합이나 실제 원문 확인을 대체하는 기능은 아닙니다.

## 평가·생성 주제와 연결

- 새 화면은 유효한 중복 검사 없이 실제 AI 평가를 실행하지 않습니다. 구버전 클라이언트의 API 호환성은 유지합니다.
- 평가 요청의 duplicate_version은 서버에서 다시 읽습니다. 자료/검색 모델/검사 기준/연구 묶음이 달라졌거나 주제·보완 입력이 다르면 재검사를 요구합니다.
- 평가 모델에는 실제 저장 자료의 ID·제목·출처와 검사 근거만 전달합니다. 임의 링크를 새로 만들지 않습니다.
- 중복 위험·검사 미완료·교사 보류 주제는 높은 점수여도 자동 추천에서 제외합니다. 검사 상태는 점수와 별도로 보여주며 별도의 ‘중복도 감점’ 계산은 하지 않습니다.
- 승인 후에도 위험 표시는 유지합니다. 검사 버전/검토가 바뀌면 평가 캐시 키도 바뀌며 이전 점수를 새 결과처럼 재사용하지 않습니다.
- 입력/생성 주제끼리 정규화 제목이 같은 경우 같은 후보 그룹으로 세어 두 후보로 부풀리지 않습니다. 실제 수상작의 동일 제목 자동 병합과는 다른 처리입니다.
- Create_Topic은 아직 구현 전입니다. 생성 주제 입력을 받을 수 있는 검사 계약과 원본/생성 사이 비교를 준비했으며 실제 자동 생성 루프를 완성한 것은 아닙니다.
- 후속 Eval_Topic 개편으로 현재 다섯 항목 가중치/80점 이상/실행 가능 상태와 중복 보류를 함께 적용합니다. [현재 평가 안내](EVAL_TOPIC.md)를 참고하세요.

## 저장·API·버전

- GET /api/duplicates/manifest: 자료/기준/검색 모델/묶음 지문, 검색 범위, 의미 검색 준비 여부. 브라우저를 다시 열 때 최신 상태를 확인합니다.
- POST /api/duplicates/check: 주제 ID·원문·원본/생성 구분·선택 보완 정보·검사 방식. 1~30개를 지원하며 앞으로의 생성 후보 비교용입니다. 원본 입력 상한은 계속20개입니다.
- POST /api/duplicates/review: 저장된 검사 버전·주제 ID·승인/보류·근거. 이전 결과를 덮어쓰지 않고 새 버전과 부모 버전을 저장합니다.
- POST /api/duplicates/group: 현재 데이터 지문·확인한 출처 ID·묶기/해제·근거. 묶음 변경도 이력을 남깁니다.

자료·검색 모델·검사 기준·연구 묶음 또는 주제 핵심 정보가 바뀌면 재검사가 필요합니다. 새 검사는 이전 승인을 자동 계승하지 않습니다. 기존 검사와 승인 이력은 남습니다. 전체 학생 계정/프로젝트 서버 저장과 공개 인증 서버로의 배포는 별도 단계입니다.

## 검증과 아직 확인하지 않은 부분

검증 명령:

```sh
python3 -m unittest discover -s backend/tests -v
npm test
```

브라우저는 테스트 전용 모의 모델 서버를 사용합니다.

```sh
python3 -m backend.tests.browser_server --port 8018
```

별도 터미널에서 Playwright/Chromium이 있을 때:

```sh
TEST_BASE_URL=http://127.0.0.1:8018 node tests/browser/phase1.mjs
TEST_BASE_URL=http://127.0.0.1:8018 node tests/browser/phase2.mjs
TEST_BASE_URL=http://127.0.0.1:8018 node tests/browser/phase3.mjs
```

실제 데이터/HTTP/SQLite를 사용해 제목 일치·상태·검토·원문 링크·출처 묶음·재검사·화면 복원·모바일을 검사합니다. 평가 점수는 모의 모델 응답입니다. 의미 검색은 테스트용 벡터와 실패 주입으로 검사하며, 이번 단계에서 실제 유료 API 호출을 하지 않습니다. 테스트에서 출처를 묶는 행동은 원문을 실제로 검증했다는 증거가 아닙니다.

Python 81개·Node 27개 자동 검사를 통과했습니다. 모의 모델 서버 외에 실제 backend.server 실행 명령을 키가 없는 임시 데이터 폴더로 실행해 제목 검사와 SQLite 저장 성공도 확인했습니다.

실제 모델/의미 검색의 품질 보정, Windows 실사용, 전체 수상작 수집·보고서 본문 확보, 공개 배포는 아직 완료하지 않았습니다.
