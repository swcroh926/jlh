# Find_Interest — 원본 주제 기반 관심사 분석

구현일: 2026년 11월 18일. 로컬 실행용이며 공개 배포하지 않았습니다.

## 사용 흐름

1. 학생 정보와 원본 주제 1~20개를 입력하고 목록을 확정합니다.
2. 후보 화면 위의 ‘원본 주제에서 관심사 찾기’를 엽니다.
3. 다음 중 하나를 선택합니다.
   - **직접 관심사 작성·수정**: 관심사/영역/근거 주제/분류 이유를 입력합니다. AI API 키와 유료 호출 없이 사용합니다.
   - **AI 관심사 분석 (API 사용)**: 비용 안내를 확인한 뒤 원본 주제만 모델에 전달합니다. 자동 호출하지 않습니다. 기존 OpenAI 어댑터를 재사용하며 Gemini/로컬 모델 연결은 아직 없습니다.
4. 초안의 관심 영역·이름·이유·근거 주제를 수정합니다. ‘관심사 분류 확정’을 누릅니다.
5. 확정한 프로필이 실제 평가의 관심도 근거로 전달됩니다. 새 화면의 실제 AI 평가는 관심사를 확정하기 전까지 비활성화합니다. 기존 예시 후보 카드는 보존합니다.

후속 Check_Duplicate 단계도 연결되어, 현재 실제 평가에는 관심사 확정 외에 유효한 중복 검사가 필요합니다. 무료 제목 검사를 먼저 사용할 수 있으며 [중복 검사 안내](CHECK_DUPLICATE.md)를 참고하세요.

별도 대화창은 없고 입력란·체크박스·확인 화면으로 처리합니다. 선생님이 분류를 수정하면 확정 전까지 이전 관심도 평가를 현재 결과로 사용할 수 없습니다.

## 계산 규칙

영역은 물리 / 화학 / 생물 / 산업 및 에너지(SW·IT 포함) / 지구 및 환경입니다. 한 관심사에 복수 영역, 한 주제에 복수 관심사를 허용합니다.

- 관심사별 개수 = 근거 원본 주제 ID의 중복을 제거한 개수
- 비율 = 해당 개수 ÷ 원본 전체 개수 × 100 (소수점 첫째 자리)
- 영역별 개수 = 해당 영역에 속한 모든 관심사의 근거 ID의 합집합 크기
- 같은 단어를 반복해도 같은 원본 주제는 한 번만 셉니다.
- 여러 영역에 속할 수 있으므로 비율의 합이 100%를 넘을 수 있습니다.
- AI가 개수/비율을 제안하더라도 채택하지 않고 서버가 재계산합니다.
- 생성 주제는 프런트엔드의 원본 목록 추출에서 제외하고, API 요청에 들어오면 서버에서 거절합니다.

관심사를 추정할 수 없다면 빈 관심사 목록과 불확실성 이유를 입력해 ‘미정’으로 확정할 수 있습니다. 근거 없는 관심사를 억지로 만들지 않습니다.

## API 계약

### POST /api/interests/analyze

```json
{"topics":[{"id":"원본-고유-ID","originalText":"학생의 원래 주제","origin":"original"}]}
```

이름·지역·학년·예산 등은 분석 입력으로 전달하지 않습니다. 모델 요청은 검증한 원본 주제 ID와 표현만 포함합니다. 학생이 주제 본문 자체에 개인정보를 적었다면 이를 자동으로 익명화하는 기능까지 있는 것은 아닙니다.

정해진 JSON schema로 영역·구체적 관심사·근거 ID·추정 이유·불확실성을 받습니다. 응답 완료 여부와 모든 ID/영역/형식을 검사한 후에만 초안으로 저장합니다. AI 오류를 ‘관심사 없음’으로 처리하지 않습니다.

### POST /api/interests/confirm

```json
{
  "topics":[{"id":"a","originalText":"식물 성장 비교","origin":"original"}],
  "interests":[{"label":"식물 성장","domains":["생물"],"reason":"원본 질문에서 추정","source_topic_ids":["a"]}],
  "uncertainties":["실제로 선호하는지는 선생님 확인 필요"],
  "base_version":null
}
```

이 API는 모델을 호출하지 않습니다. 알려진 원본 ID만 허용하고 개수·비율을 계산합니다. 이전 초안/확정본을 수정하는 경우 base_version을 연결하고, 그 원본 목록이 현재 목록과 같은지 확인합니다.

응답에는 interests, domain_summary, total_original_topics, unassigned_topic_ids, uncertainties, confirmed, version, parent_version, criteria_version, model, usage, created_at 등이 들어갑니다. AI 초안은 confirmed=false, 선생님 확정 결과는 true입니다.

## 평가와 연결

클라이언트는 실제 평가 요청에 interest_version을 넣습니다. 서버는 SQLite에서 해당 확정본을 다시 읽고 원본 목록이 일치하는지 검사합니다. 초안·존재하지 않는 버전·다른 주제의 버전은 평가 전에 거절합니다.

검증한 프로필만 모델 문맥의 confirmed_interest_profile로 전달합니다. 사용자가 계산값이나 근거를 평가 요청에 임의로 넣어도 그 값을 신뢰하지 않습니다.

관심사 버전은 평가 캐시 키에 포함하므로 수정 후에는 이전 관심도 점수를 재사용하지 않습니다. 관심사 단계에서 평가 지침 버전을 science-title-evaluation-v1.1-interests로 갱신했고, 후속 중복 근거 연결로 현재 버전은 science-title-evaluation-v1.2-duplicate-evidence입니다. **다섯 항목/가중치/80점 개편은 아직 다음 작업입니다.**

기존 API와 캐시의 호환성을 위해 구버전 클라이언트의 interest_version 없는 평가 요청까지 서버에서 강제 차단하지는 않습니다. 새 화면에서는 관심사 확정을 요구합니다.

## 저장과 재검토

- 개발 서버의 .local/interests.sqlite3: 분석 초안·선생님 수정/확정 버전, 부모 버전, 모델/지침/토큰 사용량(AI 응답에 있는 경우), 생성 시각을 저장합니다. 재시작 후에도 읽을 수 있습니다.
- 동일 원본/모델/기준의 AI 분석 초안은 24시간 재사용합니다. 확정본을 AI 초안으로 덮어쓰지 않고 별도 버전으로 저장합니다.
- 브라우저: 프로젝트와 연결한 결과, 수정 중 내용, 이전 결과 이력을 저장합니다. 새로고침 후 수정 중 내용을 복원합니다.
- 원본을 바꾸면 이전 관심사는 재검토 상태입니다. 이전 결과와 기록을 지우지 않고 새 원본으로 다시 확정해야 합니다.
- 예산·장소만 바뀌면 원본 관심사 분류를 다시 만들 필요는 없지만 실행 현실성 평가/계획은 기존 규칙대로 재검토 대상입니다.

이 단계의 API는 기존 localhost 개발 서버에만 추가했습니다. 공개 서버 인증·프로젝트 소유권·대시보드까지 구현한 것은 아닙니다. AI 프로필 저장 파일과 브라우저 연결값 중 하나를 지우거나 다른 서버로 옮기면 프로필을 다시 확정해야 합니다. SQLite 파일은 공개하거나 Git에 커밋하지 않습니다.

## 검증

```sh
npm test
python3 -m unittest discover -s backend/tests -v
```

브라우저 회귀 검증은 테스트 전용 서버로 실행합니다. 외부 모델을 호출하는 대신 모의 모델 응답을 반환하지만 HTTP/SQLite/검증/분류 계산/화면은 실제 구현을 사용합니다.

터미널1:

```sh
python3 -m backend.tests.browser_server --port 8014
```

터미널2 (Playwright/Chromium 필요):

```sh
TEST_BASE_URL=http://127.0.0.1:8014 node tests/browser/phase1.mjs
node tests/browser/phase2.mjs
```

검사 범위: 원본 ID·생성 제외, 반복 단어/중복 근거, 복수 관심 영역, 비율 합집합, 교사 수정, 이전 버전 보존, 저장/재시작, 평가 캐시 무효화, AI 형식 오류 미저장, 개인정보 필드 제외, 비용 확인 취소, 키 없는 직접 확정, 브라우저 복원, 모바일.

이 단계에서 실제 유료 OpenAI 호출을 하지 않았습니다. **구현 검증과 실제 모델 분류 품질 검증은 별개**이며, 선생님 사례로 오분류·불확실성 표시를 검토해야 합니다.
