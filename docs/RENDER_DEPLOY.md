# Render 배포 안내 — 처음 설정하는 분을 위한 순서

이 문서는 **배포 준비가 끝난 상태**의 안내입니다. Render 계정 생성·서비스 생성·결제는 아직 실행하지 않았습니다.

## 무엇이 바뀌나요?

현재 `https://swcroh926.github.io/jlh/`는 GitHub Pages에서 화면 파일을 제공합니다. 새 Render 주소는 **화면과 AI 서버를 함께** 제공합니다. 사용자는 새 주소에서 기존 앱을 열고 접근 코드로 AI 평가를 사용할 수 있습니다. Render 주소가 정해지면 GitHub Pages에도 이동 안내를 붙일 수 있습니다.

OpenAI 키는 Render 서버에만 보관합니다. 선생님/테스터에게는 별도로 정한 접근 코드를 전달합니다. 접근 코드와 OpenAI API 키는 다른 값입니다. 학생 이름과 계정을 만드는 정식 로그인 기능은 아직 없습니다.

## 비용을 먼저 확인하세요

이 설정은 Render의 **Starter 웹 서비스 1개 + 1GB 영구 디스크**를 요청합니다. 무료 플랜이 아닙니다. SQLite 평가 결과·사용 한도·검색 색인을 재배포/재시작 이후에도 보존하기 위해 영구 디스크를 선택했습니다.

Render 화면에 표시되는 서비스·디스크 요금을 확인한 뒤 생성하세요. OpenAI API 호출 비용은 별도입니다. 이 채팅에서는 유료 Render 리소스를 생성하지 않았습니다.

## 1. Render 계정과 GitHub 연결

1. https://dashboard.render.com/ 에서 계정을 만듭니다. GitHub 계정으로 로그인할 수 있습니다.
2. GitHub 연결을 요청하면 `swcroh926/jlh` 저장소 접근을 허용합니다.
3. **New → Blueprint**에서 이 저장소를 선택합니다. 메뉴 이름은 UI 변경에 따라 조금 다를 수 있습니다.
4. 저장소의 `render.yaml`을 읽으면 `jlh-science-lab` 웹 서비스와 디스크가 표시됩니다.

설정 파일 직접 보기: https://github.com/swcroh926/jlh/blob/main/render.yaml

## 2. 비밀 값 두 가지 입력

Blueprint 생성 화면에서 아래 값을 요구합니다. 키와 접근 코드는 채팅이나 GitHub 파일에 적지 마세요.

### LLM_API_KEY

OpenAI에서 발급한 실제 API 키를 Render 환경 변수/시크릿 입력란에 넣습니다. Codex에 등록했던 값은 Render로 자동 전달되지 않습니다. Render용으로 별도 OpenAI 프로젝트 키를 발급하면 개발 환경과 사용량을 나누어 관리할 수 있습니다.

### BETA_ACCESS_CODES

접근할 사람의 식별자와 접근 코드를 JSON으로 입력합니다. 식별자는 영문·숫자·밑줄·하이픈 1~40자, 코드는 **16자 이상의 예측하기 어려운 값**이어야 합니다. 한 사람당 다른 코드를 사용하면 사용자별 제한이 적용됩니다.

형식 예시 (문구를 그대로 사용하지 말고 실제 코드로 바꾸세요):

```json
{"teacher":"여기에_직접_정한_긴_접근코드"}
```

두 명에게 허용하려면:

```json
{"teacher":"첫번째_사람의_긴_접근코드","tester":"두번째_사람의_다른_긴_접근코드"}
```

접근 코드는 실제 이름이나 다른 서비스 비밀번호로 만들지 마세요. 식별자는 서버의 사용량 관리에만 사용합니다. 코드가 변경되면 해당 사용자의 기존 세션도 무효화됩니다.

### 자동 설정되는 값

- SESSION_SECRET: Render가 생성합니다. 브라우저 세션 서명용이며 임의로 공개하지 마세요.
- DATA_DIR: `/var/data/jlh` (영구 디스크)
- PYTHON_VERSION: 3.12.11
- PUBLIC_ORIGIN: Render가 제공하는 `RENDER_EXTERNAL_URL`을 자동 사용하므로 따로 입력할 필요가 없습니다. 나중에 사용자 도메인을 사용한다면 `PUBLIC_ORIGIN=https://도메인`을 별도 지정합니다.

## 3. 검토 후 배포

1. 서비스 플랜과 디스크 비용, 입력값을 검토합니다.
2. 생성/배포를 실행합니다.
3. 빌드와 배포가 끝나고 서비스가 Live가 될 때까지 기다립니다.
4. 화면 상단에 표시된 **실제 Render 주소**를 엽니다. 이름 중복 등에 따라 주소는 달라질 수 있으므로 임의로 추측하지 마세요.
5. 아이디어를 입력하고 후보 화면에서 **선생님용 접근 코드**를 입력합니다. ‘AI 평가 연결’을 누릅니다.
6. 아이디어 1개로 평가해 봅니다. 이름은 AI에 전달하지 않습니다.

배포 로그나 설정을 공유할 때 환경 변수의 값·접근 코드는 가려주세요. 사이트 주소와 오류 메시지만 있으면 먼저 진단할 수 있습니다.

## 4. 의미 검색 활성화

처음 Render 배포에는 Codex의 `.local` 파일이 전달되지 않습니다. **초기에는 제목 표현 검색 + 실제 AI 평가**로 동작합니다. 서버 색인이 없는데 의미 검색이라고 표시하지 않습니다.

의미 검색을 활성화하려면 서비스의 **Shell**에서 다음 명령을 한 번 실행합니다.

```sh
python -m backend.server --build-index
```

이 명령은 지도논문을 제외한 현재 제목 2,190건을 OpenAI 임베딩 API로 변환합니다. **추가 API 비용이 발생**하며, 배치별로 저장해 실패하면 재실행으로 이어갈 수 있습니다. 이전 Codex 색인을 자동으로 전송한 것은 아닙니다.

완료 후 Render 서비스 메뉴에서 재시작합니다. 실제 데이터가 맞는 완성된 색인이 있을 때만 서버가 이를 읽습니다. `/api/health`의 search_mode가 `semantic`인지 확인합니다. `lexical`이면 제목 표현 검색입니다. 재배포할 때 영구 디스크는 유지됩니다.

자동 배포마다 유료 색인을 다시 만들지 않도록 빌드/시작 명령에는 이 단계를 넣지 않았습니다.

## 5. 접근과 사용량 제한

- 화면과 제목 검색은 접근 코드 없이 볼 수 있습니다. 실제 AI 평가는 접근 코드가 필요합니다.
- 브라우저에 Secure·HttpOnly·SameSite=Strict 쿠키를 사용합니다. 세션은 12시간입니다.
- ‘연결 해제’는 현재 브라우저 쿠키를 지웁니다. 다른 기기의 세션까지 강제 종료하려면 해당 접근 코드를 교체하세요.
- 사용자별 1시간에 최대 5회, 전체 1시간 10회, 최근 24시간 30회·아이디어 200개까지입니다.
- 한 번에 아이디어 1~20개, 동시 평가 1개입니다.
- 유효한 평가 요청은 실패하거나 캐시를 사용해도 요청 횟수에 포함됩니다. 오류 때문에 자동으로 유료 요청을 반복하지 않습니다.
- 한도 예약은 SQLite에 저장해 프로세스 재시작 후에도 남습니다. 1개 서비스/1개 워커를 전제로 합니다. 임의로 워커나 서비스 복제 수를 늘리지 마세요.
- 요청 수 제한은 금액 상한이 아닙니다. OpenAI 프로젝트의 비용·사용량도 확인해야 합니다.
- 평가 결과는 로컬 SQLite에 저장합니다. 사용자별 결과 조회 기능은 없고, 동일 입력의 캐시는 공유됩니다. 학생별 클라우드 프로젝트 동기화나 정식 계정 시스템은 아직 없습니다.
- 접근 코드 오입력을 제한합니다. 서비스 프록시 설정에 따라 여러 사용자가 같은 IP 버킷을 공유할 수 있어, 반복 오입력 후에는 잠시 기다려야 합니다.

## 6. 문제가 생기면

- **서버 시작 실패**: BETA_ACCESS_CODES가 올바른 JSON인지, 코드가 16자 이상인지 확인합니다.
- **사이트 주소를 확인해주세요**: Render 기본 주소와 PUBLIC_ORIGIN(직접 설정했다면)이 일치하는지 확인합니다.
- **접근 코드가 올바르지 않음**: JSON 전체가 아닌 해당 코드의 값만 화면에 입력하세요. API 키를 입력하는 곳이 아닙니다.
- **AI 연결 권한 오류**: LLM_API_KEY의 프로젝트와 유효성을 확인합니다.
- **크레딧/결제 한도 오류**: OpenAI API 결제·프로젝트 한도를 확인합니다.
- **사용 한도 오류**: 앱 자체의 요청 제한 또는 OpenAI 요청 제한입니다. 운영 로그에 키를 출력하며 확인하지 마세요.
- **제목 표현 검색 표시**: 서버에서 색인을 만들고 재시작했는지 확인합니다.

## 개발 검증과 실제 배포 구분

프로젝트에는 인증/세션 변조/출처 검증/지속형 제한/잘못된 입력/비공개 파일 접근 등의 자동 테스트가 있습니다. Gunicorn을 직접 실행해 브라우저에서 잘못된 코드, 연결, 실제 평가 캐시 표시, 새로고침, 연결 해제, 모바일 화면을 검증했습니다. 이는 Render에서의 실제 배포 성공을 의미하지 않습니다. 계정 생성과 서비스 배포 후 실제 URL에서 다시 확인해야 합니다.
