# 기능명세서

# JLH 기능명세 v1.0 — 학생 정보·주제 선정·실험 설계

본 문서는 첫 구현을 위한 명세다. 초기 기본값은 선생님 설정에서 변경할 수 있다. 공개 배포는 이번 범위에 포함하지 않고 로컬에서 실행·검증한다.

## 1. 목표와 범위

학생의 관심사와 수행 조건을 바탕으로 탐구 주제를 평가·생성하고, 선택한 주제를 검증할 수 있는 실험 계획을 제공한다.

구현 흐름:

학생 정보 및 주제 목록 입력

→ 관심사 분석

→ 주제 평가

→ 필요하면 새 주제 생성·재평가

→ 후보 비교 및 최종 주제 선택

→ 실험 계획 생성

별도 대화형 화면은 만들지 않는다. 정보 보완은 입력란·확인 화면으로 처리한다.

이번 범위에서 제외되지만, 추후에 할 것

- 선생님 로그인 및 대시보드에서 학생별 관리
- 공개 배포
- 실험 결과 분석과 최종 보고서 생성
- 수상 확률 예측과 표절 확정 판정

## 2. 공통 설정과 학생 정보

### 2.1 선생님 기본 설정

| 항목 | 초기 기본값 | 설명 |
| --- | --- | --- |
| 학생별 재료비 한도 | 300,000원 | 학생별로 변경 가능 |
| 준비 기간 | 8주 | 프로젝트별로 변경 가능 |
| 수업 빈도 | 주 1회 | 첫 버전 일정 산정 기준 |
| 회당 수업 시간 | 3시간 | 프로젝트별로 변경 가능 |
| 실험 장소 | 학원 | 최초 사용 시 선생님 입력 |

기본값 변경은 기존 프로젝트에 자동으로 덮어쓰지 않는다. 새 프로젝트에 적용하고, 기존 프로젝트는 명시적으로 변경한다.

### 2.2 학생 입력

필수:

- 이름 또는 별명
- 학년
- 지역

선택:

- 학생별 재료비 한도

재료비 미입력 시 선생님 기본값을 적용한다. 0원은 미입력과 구분하여 인정한다.

이름과 지역은 화면과 저장에 사용하며 AI 요청에서 제외한다. 

## 3. 주제 목록 입력

### 3.1 입력 방식

- 직접 텍스트 입력
- TXT, DOCX, HWPX 파일에서 텍스트 추출
- 기존 HWP 파일은 변환 도구로 추출을 시도한다. 실패하면 HWPX·DOCX·TXT 변환 방법을 안내한다.

스캔 문서의 OCR은 첫 버전에서 제외한다.

### 3.2 처리 규칙

- 원본 주제는 1~20개다.
- 파일 추출 후 주제 구분 결과를 사용자에게 보여주고 수정·확정하게 한다.
- 완전히 동일한 주제는 중복으로 안내한다.
- 의미가 비슷하다는 이유만으로 서로 다른 주제를 자동 삭제하지 않는다.
- 원래 표현을 보존한다. AI가 다듬은 제목은 별도 항목으로 저장한다.
- 파일을 다시 불러와도 기존 내용을 확인 없이 덮어쓰지 않는다.

## 4. 관심사 분석 — Find_Interest

### 입력

학생이 확정한 원본 주제 목록.

### 출력

- 관심 영역
- 구체적인 관심 주제
- 각 관심사의 근거가 된 원본 주제 ID
- 관련 원본 주제 수와 비율
- 분류 불확실성

### 영역

1. 물리
2. 화학
3. 생물
4. 산업 및 에너지 — SW·IT 융합 포함
5. 지구 및 환경

복수 영역·복수 관심 주제를 허용한다.

### 판단 규칙

- 단어 등장 횟수보다 ‘해당 관심사와 관련된 원본 주제의 개수’를 센다.
- 한 주제에서 같은 단어가 반복되어도 여러 번 가산하지 않는다.
- 관심사마다 학생이 입력한 어떤 주제에서 추정했는지 표시한다.
- 입력 목록에서 추정한 관심사임을 명시한다.
- AI가 생성한 주제는 관심도 산출의 근거에 자동 추가하지 않는다.
- 선생님이 관심사 분류를 수정할 수 있다. 수정 후에는 관심도 점수를 다시 평가한다.

## 5. 주제 평가 — Eval_Topic

### 입력

- 학년
- 평가할 주제
- 원본 목록에서 파악한 관심사
- 재료비 한도
- 준비 기간·수업 시간·수업 장소
- 검색된 관련 자료

### 출력

각 주제에 대해:

- 다섯 항목의 점수·근거
- 가중 총점
- 부족한 정보와 불확실성
- 보완 방향
- 참고한 자료와 출처
- 중복 유무
- 실행 가능 상태
- 평가 기준 및 모델 버전

### 평가 기준

| 항목 | 가중치 | 판단 내용 | 예시 |
| --- | --- | --- | --- |
| 독창성 | 30% | 기존 연구와 다른 과학적 착상, 접근 방법과 과정의 창의성 | (예 : ‘음료수로 불을 끌 수 있을까?’보다, ‘씨앗으로 불을 끌 수 있을까?’가 더 독창적인 주제) |
| 탐구성 | 30% | 연구 질문의 명확성, 측정·비교·검증 가능성, 과학적 원리 탐구 여부 | (예 : ‘씨앗으로 불을 끌 수 있을까?’ 보다, ‘자가소화씨앗캡슐 특성 및 연소특성 탐구’가 구체성 더 높음. ‘친환경 재료를 사용한 더 편한 신발 만들기’보다, ‘사람의 발 모양 분석 및 적합한 신발 구조 탐구’가 더 과학 탐구에 적합 주제. )  |
| 실험현실성 | 15% | 학년·장소·장비·재료비·기간·관찰 조건에서 수행 가능한지 |  |
| 실용성 | 15% | 문제 해결 가능성, 기존 방식 대비 개선 가능성, 학문적·현실적 가치 | (예 : 이 연구가 잘 나오면, 기존에 있던 산불 진화 방식보다 저렴한 비용으로 진화 가능할거야. 씨앗캡슐을 만드는 것도 현재 기술로 충분히 가능해. 등등) |
| 관심도 | 10% | 원본 목록에서 추정하거나 선생님이 확정한 관심사와의 관련성 |  |

전문 용어가 많다는 이유만으로 탐구성 점수를 높이지 않는다. 발명·제작 주제도 성능·구조·원리 등을 검증한다면 과학 탐구로 평가할 수 있다.

실험현실성은 수준·장소·비용·시간별 판단을 함께 제시한다. 필수 조건 하나가 불가능한데 다른 조건이 좋다는 이유로 높은 현실성 점수를 주지 않는다.

독창성은 관련 자료가 없다는 이유만으로 높은 점수를 주지 않는다.

실용성에서 기대 효과와 실제 검증된 효과를 구분한다. 제품화나 매출 가능성이 있어야만 높은 점수를 받을 수 있는 것은 아니다.

### 점수 척도

- 0~39: 핵심 조건 미충족
- 40~59: 큰 보완 필요
- 60~79: 부분적인 타당성은 있으나 보완 필요
- 80~89: 근거와 조건이 비교적 충분함
- 90~100: 해당 항목에서 매우 강한 근거가 있음

이 구간은 초기 평가 기준이며, 선생님의 모범 사례로 보정한다. 80점은 수상 가능성을 의미하지 않는다.

### 계산과 통과

총점 = 탐구성×0.30 + 실험현실성×0.15 + 독창성×0.30 + 실용성×0.15 + 관심도×0.10

- 총점은 서버 코드가 계산한다.
- 반올림 전 총점이 80 이상이면 점수 기준을 통과한다.
- 화면에는 소수점 첫째 자리까지 표시한다.
- 실행 가능 상태는 ‘가능·검토 필요·불가’로 구분한다.
- 자동 추천 후보는 총점 80 이상이면서 실행 가능 상태가 ‘가능’인 주제다.
- 조건이 부족하거나 안전성 확인이 필요한 주제는 ‘검토 필요’로 분리한다.

추천 후보가 3개 이상이면 상위 3개를 제시한다.

주제별 총점 → 평가기준별 점수(bar 형태) 및 근거(박스)로 화면에 표현한다.

### 근거의 한계

제목만 확보된 자료는 제목 수준의 비교에만 사용한다. 실험 방법의 중복, 표절, 수상 가능성을 확정하지 않는다.

## 6. 주제 생성 — Create_Topic

### 실행 조건

자동 추천 후보가 3개 미만이거나, 사용자가 생성 버튼을 클릭할 때 실행한다.

### 입력

- 평가 결과 상위 5개와 점수·근거
- 원본 목록에서 확정한 관심사
- 학생의 수행 조건
- 관련 연구와 검색 자료

주제가 5개 미만이면 존재하는 주제만 사용한다. 실행 불가로 판단된 위험한 방법은 새 주제에 그대로 계승하지 않는다.

### 출력

중복되지 않는 새 주제 10개.

각 주제에 포함할 내용:

- 제목과 쉬운 설명
- 탐구 질문
- 원본 주제와의 연결
- 생성 방법
- 보완하려는 평가 항목
- 예상 실험 개요
- 참고 출처 및 확인이 필요한 조건

### 생성 방법

- 기존 주제의 약점 보완
- 서로 다른 주제 요소 결합
- 실제 검색으로 확인한 최근 연구의 학생 수준 응용
- 관찰 대상·조건·측정 지표·비교 방법의 변경 등

소재를 바꾸거나 전문 용어를 추가한 것만으로 새롭다고 판단하지 않는다. 실제 검색을 하지 않았다면 최신 연구를 조사했다고 표시하지 않는다.

### 생성 후 처리

- 새 주제 10개를 동일한 Eval_Topic 기준으로 평가한다.
- 기존 주제와 합쳐 추천 후보를 정한다.
- 새 주제는 원본 15개 입력 한도와 별도로 관리한다.
- 최대 25개 후보를 내부적으로 비교한다.
- 생성·재평가는 자동으로 한 차례만 수행한다.
- 여전히 후보가 부족하면 부족한 이유와 보완 후보를 표시한다.
- 추가 생성은 사용자의 명시적인 실행으로 진행한다.
- 중복·형식 오류로 10개를 채우지 못하면 제한적으로 보완하고, 계속 실패하면 부분 결과와 이유를 표시한다.

## 7. 최종 주제 선택

학생·선생님이 후보를 비교해 최종 주제 하나를 선택한다. AI가 자동 확정하지 않는다.

새 주제를 직접 입력해 실험 설계로 진행할 수도 있다. 이 경우에도 최소 수행 조건과 안전성 확인을 거친다.

점수 미달 후보를 선택할 수 있으나, 보완 사항을 표시한다. 실행 불가 조건이 있는 주제는 조건 변경과 재검토 전까지 실행 가능한 계획으로 확정하지 않는다.

## 8. 실험 계획 — Set_Exp

### 입력

- 선택하거나 직접 입력한 주제
- 학년·재료비 한도·기간
- 수업 시간·장소·보유 장비
- 주제 평가 결과와 관련 자료

### 정보 부족 처리

실험 가능 여부를 좌우하는 조건이 빠졌다면 보완 입력을 요청한다.

가벼운 가정으로 작성할 수 있는 내용은 ‘가정’으로 표시한다. 검증되지 않은 가정이 포함된 계획은 초안 상태로 저장한다.

### 실험 구성

- 최소 2단계, 기본 목표는 3~4단계다. 실험에 따라 5단계를 넘어도 좋다.
- 단계 수를 맞추기 위한 불필요한 실험을 추가하지 않는다.
- 각 단계는 탐구 질문의 일부를 검증하고 다음 단계와 연결되어야 한다.
- 실험 단계 수와 동일 조건의 반복 측정 횟수는 구분한다.
- 실용성 확인이 적합한 주제는 마지막에 기존 방법·구조·재료 등과 비교하는 실험을 제안한다.

### 단계별 출력

- 실험명과 목적
- 가설 또는 확인할 질문
- 독립·종속·통제 변수
- 필요한 경우 대조군·비교 대상
- 구체적인 절차
- 측정 대상·단위·도구
- 반복 횟수와 선정 근거
- 기록표
- 결과에 따른 다음 단계의 판단 기준
- 준비물·시간·주의 사항

### 준비물과 비용

표 항목:

품목 / 규격 / 수량 / 단가 / 소계 / 보유 여부 / 가격 근거 / 구매 링크 / 확인일

- 보유 물품은 신규 구매비와 분리한다.
- 재사용 물품은 단계별로 중복 합산하지 않는다.
- 배송비가 미확인이면 총액에 별도 표시한다.
- 실제 확인 가격과 추정 가격을 구분한다.
- 구매 링크와 가격을 만들어내지 않는다.
- 서버 코드가 총액을 계산한다.
- 예산 초과 시 대체 재료·규모 축소안을 제시한다. 해결되지 않으면 초과 상태를 명시한다.

### 일정

주 1회 수업을 기준으로 주차별 일정을 제공한다.

구분:

- 수업 중 실제 작업 시간
- 실험 사이 관찰·관리 시간
- 생육·건조 등 대기 시간
- 재측정·확인 실험 시간

작업 시간만 합쳐 준비 기간을 산정하지 않는다. 기간 초과 시 축소안을 제안하며, 가능한 것으로 꾸미지 않는다.

### 계획 확정

선생님이 검토 후 확정한다. 필요한 경우 조건을 수정하고 계획 재생성을 실행할 수 있다. 이전 계획은 보존한다.

작품요약서는 제공받은 후 실험 구성과 설명 수준을 검토하는 기준 예시로 반영한다.

## 10. 검증 및 완료 기준

### 기능 검증

- 재료비 미입력 시 기본값을 적용하고 0원과 구분한다.
- 원본 주제 15개 제한과 파일 추출 확인 절차가 작동한다.
- 복수 관심 영역과 근거 주제 ID가 표시된다.
- 총점·80점 기준·통과 개수·정렬이 계산 규칙과 일치한다.
- 후보 부족 시 10개 생성과 재평가를 한 차례 수행한다.
- 생성 주제가 원래 관심사 산출에 섞이지 않는다.
- 선택 주제로 최소 2단계의 실험 계획을 생성한다.
- 비용 중복 합산과 예산·기간 초과를 표시한다.
- 서버 재시작 후 저장한 프로젝트와 계획을 다시 읽는다.
- AI 오류를 성공 결과로 저장하지 않는다.

### AI 품질 검증

선생님이 검토한 초기 사례 20~30개를 마련한다. 이 자료는 초기 비교·오류 발견용이며 정확성 입증용 표본으로 간주하지 않는다.

중점 검토:

- 전문 용어만 늘렸을 때 탐구성을 과대평가하지 않는가
- 흔한 과학 상식과 새로운 검증 질문을 구분하는가
- 예산·기간·관찰 조건 변경을 평가와 계획에 반영하는가
- 근거 없는 출처·가격·과학적 효과를 만들어내지 않는가
- 연구 질문을 실제로 검증하는 실험을 구성하는가

시험용 사례의 정답을 지침에 그대로 넣지 않는다. 기준과 모델을 변경할 때 같은 시험 사례로 비교한다.

## 11. 구현 순서

1. 기존 데이터·화면을 새 학생 조건 및 주제 15개 입력 규칙에 맞춘다.
2. Find_Interest를 구현한다.
3. 기존 평가 기능을 5개 항목·가중치·80점 분기로 수정한다.
4. Create_Topic과 재평가를 연결한다.
5. 최종 주제 선택과 Set_Exp를 구현한다.
6. 저장·버전 관리와 기능·품질 검증을 마무리한다.

각 단계가 끝나면 변경 내용, 직접 확인하는 방법, 남은 한계를 설명한다.

**JLH 기능명세 v1.1 추가 — 주제 중복 위험 검사**

기존 v1.0 명세에 다음 기능과 처리 규칙을 추가한다.

**1. 수정된 전체 흐름**

학생 정보·원본 주제 입력

→ Find_Interest

→ Check_Duplicate — 기존 수상작과 유사성 검사

→ Eval_Topic — 유사 연구를 참고하여 평가

→ 후보 부족 시 Create_Topic

→ 생성 주제의 중복·유사성 검사

→ Eval_Topic 재평가

→ 최종 주제 선택

→ Set_Exp

직접 입력한 주제를 실험 설계로 보내는 경우에도 기존 수상작 검사를 수행한다.

**2. 중복 위험 검사 — Check_Duplicate**

**목적**

전국·서울에서 수집한 기존 수상작과 유사한 주제를 찾아 보여주고, 주제 선정 전에 차별성을 검토할 수 있게 한다.

**입력**

- 검사 대상 주제 ID와 원문
- 주제의 탐구 질문·대상·방법·측정 지표 — 제공된 경우
- 전국·서울 수상작 데이터

**검색 대상**

- 저장된 데이터베이스의 작품을 기본 대상으로 한다.
- 지도논문은 기본 검사에서 제외하고, 별도 참고 검색 옵션으로 제공한다.
- 동일 작품이 지역·전국에 함께 등재된 것으로 확인되면 한 연구로 묶되 출처 링크는 보존한다.
- 제목이 같다는 이유만으로 서로 다른 작품을 자동 병합하지 않는다.

**검사 방식**

1. 공백·기호·표현 차이를 정규화해 동일·유사 제목을 찾는다.
2. 의미 검색으로 표현은 달라도 연구 내용이 가까운 후보를 찾는다.
3. 후보와 대상 주제의 공통점·차이점을 비교한다.
4. 실제 확보한 정보 범위에서 위험 상태를 결정한다.

가능하면 다음을 비교한다.

- 탐구 대상
- 연구 질문
- 바꾸는 조건
- 측정 대상
- 접근 방법

제목에 없는 실험 방법이나 결과를 추측하여 사실처럼 비교하지 않는다.

**출력**

- 상태: `중복 위험` / `유사 연구 있음` / `현재 자료에서 뚜렷한 유사 연구 미발견` / `검사 미완료`
- 판단 근거
- 유사 연구 상위 5건 이내
- 자료별 제목·연도·지역 또는 출처·원문 링크
- 유사한 부분과 확인 가능한 차이
- 추가로 확인해야 할 내용
- 차별성을 높이기 위한 보완 방향
- 검사에 사용한 데이터·검색 방식·버전

‘미발견’은 독창성 보장이나 전체 선행 연구 검색 완료를 의미하지 않는다.

**3. 상태 판단**

**중복 위험**

제목이 같거나 매우 가깝거나, 확보한 정보에서 핵심 탐구 질문과 접근이 상당히 겹치는 경우 표시한다.

동일 제목이라도 실제 연구가 같다고 확정하지 않는다. 판단 근거에 ‘제목 기준’ 등 자료 수준을 명시한다.

**유사 연구 있음**

소재나 분야는 겹치지만, 질문·변수·방법의 차이가 있거나 현재 자료만으로 높은 중복 위험을 판단하기 어려운 경우 표시한다.

**뚜렷한 유사 연구 미발견**

현재 검색 범위에서 관련성이 높은 후보를 찾지 못한 경우 표시한다.

**검사 미완료**

검색 실패·데이터 오류 등이 발생한 경우다. 오류를 ‘유사 연구 없음’으로 처리하지 않는다.

의미 검색의 유사도 수치를 중복 확률로 표시하지 않는다. 높은 위험으로 분류할 기준은 선생님이 검토한 유사·비유사 사례로 보정한다.

**4. 주제 평가와 연결**

- Eval_Topic은 중복 검사 결과와 유사 연구를 입력으로 받는다.
- 독창성 평가 근거에 어떤 선행 연구와 무엇이 비슷하거나 다른지 설명한다.
- 같은 소재라는 이유만으로 독창성을 낮게 평가하지 않는다.
- 제목 표현만 바꾼 것을 차별성으로 인정하지 않는다.
- 근거 없이 중복도만큼 총점을 감점하는 별도 계산은 추가하지 않는다.
- 중복 위험 표시는 총점과 별도로 유지한다.

`중복 위험` 주제는 80점 이상이어도 자동 추천 확정 대상에서 보류한다. 선생님이 차별성을 검토하여 승인하거나, 보완 후 재검사하면 추천 대상으로 전환할 수 있다.

자동 추천 후보 3개를 셀 때는 점수·실행 가능 조건과 함께 중복 위험 검토 상태를 확인한다.

**5. 주제 생성과 연결**

Create_Topic에는 기존 주제의 유사 연구와 중복 위험 근거도 전달한다.

생성 후에는 다음을 검사한다.

1. 전국·서울 기존 수상작과의 유사성
2. 학생의 원본 주제와의 유사성
3. 새로 생성한 주제끼리의 유사성

원본 주제의 발전안은 허용하되 무엇을 보완했는지 표시한다. 제목만 바꾼 제안이나 사실상 같은 생성 주제는 서로 다른 후보로 세지 않는다.

위험이 높은 생성 주제는 보완·교체를 시도한다. 보완 후에도 차별성을 확보하지 못하면 위험 표시와 함께 검토 대상으로 남긴다.

**6. 화면 표시**

원본·생성 주제 카드 모두에 검사 상태를 표시한다.

‘중복 위험’ 또는 ‘유사 연구 있음’을 선택하면:

- 유사 연구 목록
- 원문 링크
- 비슷한 부분
- 확인 가능한 차이
- 보완 방향

을 펼쳐 볼 수 있게 한다.

총점이 높더라도 위험 표시를 숨기지 않는다. 참고 자료는 실제 데이터에 존재하는 ID·링크만 표시한다.

**7. 저장 및 재검사**

주제별 검사 결과·근거·참고 연구·선생님 검토 상태를 저장한다.

다음 경우 재검사가 필요하다.

- 주제의 핵심 질문·방법 변경
- 수상작 데이터 갱신
- 검색 모델·검사 기준 변경

이전 검사 결과와 검토 기록은 버전으로 보존한다.

**8. 완료 기준**

- 동일 제목·표현이 조금 다른 유사 제목을 찾는다.
- 같은 소재지만 다른 연구 질문을 무조건 고위험으로 분류하지 않는다.
- 원본 주제와 생성 주제 모두 검사한다.
- 생성 주제끼리의 사실상 중복을 제거한다.
- 자료에 없는 연구·링크를 제시하지 않는다.
- 검색 실패를 ‘중복 없음’으로 표시하지 않는다.
- 위험 상태가 평가·후보 선정·화면·저장에 일관되게 반영된다.
