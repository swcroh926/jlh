# Eval_Topic — 다섯 항목 가중 평가

2026년 11월 18일, 작업 브랜치의 로컬 개발 기능입니다. 공개 배포하지 않았습니다.

## 사용자 기능과 전체 흐름

입력 → 관심사 확정 → 중복 검사 → **가중 평가·수행 조건 검토** → 주제 생성/재평가 → 최종 주제·실험 계획 순서입니다. 이번 단계는 굵게 표시한 평가 기능입니다. 자동 생성과 주제별 실험 계획은 아직 없습니다.

기존에는 네 항목 평균이 기준값(기본70점)을 초과하면 통과했습니다. 이제 다음 기준을 사용합니다.

| 항목 | 가중치 |
| --- | ---: |
| 독창성 | 30% |
| 탐구성 | 30% |
| 실험현실성 | 15% |
| 실용성 | 15% |
| 관심도 | 10% |

모델은 각 항목의 정수 점수·근거, 부족한 정보·보완 방향·검증된 출처 ID, 수행 조건별 판단을 제안합니다. 총점·통과·최종 실행 상태·추천 순위는 Python 서버가 계산합니다. 모델을 파인튜닝한 것은 아닙니다.

## 통과와 추천은 다릅니다

- 반올림 전 가중 총점이 **80 이상**이면 점수 통과입니다. 예전 요청에서 threshold를0 또는99로 보내도 새 기준은80입니다. 잘못된 형식의 값은 거절합니다.
- 화면은 소수점 첫째 자리로 반올림합니다. 79.95는80.0으로 보이지만 점수 미달입니다.
- 학년·장소·장비·비용·시간/대기·관찰·안전을 각각 가능/검토 필요/불가와 이유로 보여줍니다.
- 어느 조건이든 불가이면 전체 불가, 불가가 없고 검토 필요가 있으면 전체 검토 필요입니다. 모두 가능일 때 전체 가능입니다.
- **점수80 이상 + 전체 가능 + 중복 검토 보류 없음**인 후보만 자동 추천에 포함합니다. 후보3개 이상이면 반올림 전 총점 상위3개를 제시하며 동점은 입력 순서로 정합니다.
- 같은 제목 후보의 중복 집계 방지, 위험 표시 유지, 근거를 남긴 교사 중복 검토는 계속 적용합니다. 중복 승인만으로 실행 불가를 해제할 수 없습니다.
- 같은 소재를 이유로 무조건 감점하거나, 전문 용어·매출 가능성을 필수 조건으로 보지 않습니다. 제목 자료만으로 독창성이나 수상 확률을 보장하지 않습니다.

현재 수행 상태는 AI가 제안한 조건별 판단을 서버가 종합한 보조 의견입니다. 실제 가격 검색·장비 확인·현장 안전 검증을 수행한 결과가 아닙니다. 정보 부족은 검토 필요로 제시하도록 지침에 명시했습니다. 실제 사례에서 이 판단의 정확도를 검증해야 합니다.

## 어디가 바뀌었나요?

| 부분 | 역할 |
| --- | --- |
| 화면 | 다섯 항목 점수 막대·가중치·근거, 가중 총점, 점수 통과와 실행 상태 구분, 조건별 이유 |
| Python | 점수/출처/조건 응답 검증, 가중 합산·반올림·80점 경계·추천 필터·순위 |
| AI | 새 응답 계약과 평가 지침. 제공자는 기존 OpenAI 유지, 추가 모델 학습 없음 |
| 저장소 | 기존 SQLite 평가 캐시에 새 기준 버전·가중치·조건별 근거 저장. 과거 평가/노트 보존 |

## 이전 결과와 호환

새 기준 버전은 science-weighted-evaluation-v2입니다. 서버 캐시 키와 브라우저 평가 키를 갱신했습니다. 예전 4항목 결과는 삭제하지 않고 ‘이전 4항목 기준/재평가 필요’로 보여줍니다. 과거 결과를 새 기준의 후보로 선택할 수 없습니다. JSON average 필드는 기존 소비자를 위한 표시값으로 남기되, 새 결과에서는 가중 총점의 반올림 값이며 weighted_total이 반올림 전 총점입니다. weights 필드로 새 형식을 구분합니다.

전체 프로젝트의 서버 저장·기기 간 동기화는 아직 없고, 프로젝트 연결은 브라우저, 평가 캐시는 .local/evaluations.sqlite3에 있습니다. .local을 보존해야 합니다.

## 선생님이 직접 확인하기

1. 최신 개발 브랜치 ZIP으로 코드만 업데이트하고 기존 .local을 유지합니다.
2. START_LOCAL.bat에서는 새 화면·고정80점 안내·기존 기록 보존을 무료로 확인합니다. 실제 AI 평가는 실행하지 않습니다.
3. 실제 평가를 확인하려면 무료 실행 창을 닫고 START_AI_LOCAL.bat를 실행합니다. 기존 안내대로 비용 동의 후 OpenAI 키를 숨김 입력합니다. 실제 API 비용이 발생할 수 있습니다.
4. 학생 조건·주제를 입력하고 원본 목록을 확정합니다. 관심사 분류를 확인/확정하고 제목 기준 중복 검사를 완료합니다.
5. 후보 화면 아래 ‘아이디어 AI 평가’에서 장비·공간을 구체적으로 적고 ‘전체 …개 아이디어 평가’를 누릅니다.
6. 다섯 점수·가중 총점·실행 가능 상태와 조건별 근거를 확인합니다. 점수 통과여도 검토 필요/불가·중복 보류이면 추천에 포함되지 않는지 확인합니다.
7. 새로고침해 결과가 유지되는지, 조건 변경 시 재평가 안내가 나오고 실험 노트는 남는지 확인합니다.

## 개발 검증

```sh
python3 -m unittest discover -s backend/tests -q
npm test
```

테스트 모델 서버를 실행하고 Playwright/Chromium 환경에서:

```sh
python3 -m backend.tests.browser_server --port 8020
TEST_BASE_URL=http://127.0.0.1:8020 node tests/browser/phase4.mjs
```

이 서버는 모의 모델 전용이며 실제 AI 품질을 시험하는 서버가 아닙니다. ROUNDING/REVIEW/BLOCKED로 시작하는 테스트 제목은 이 서버 안에서만 경계 사례 응답을 만듭니다. 일반 backend.server에는 이런 동작이 없습니다.

자동 검사는79.95 경계·80 포함·가중 순위·불가/검토 필요 고득점 보류·조건 누락/잘못된 상태 거절·이전 캐시 분리·중복 위험 회귀를 다룹니다. 브라우저는 실제 HTTP·SQLite·계산·화면과 모의 AI 응답을 조합합니다. 실제 유료 모델 호출·Windows 실사용·공개 배포와 구분합니다.
