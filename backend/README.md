# OpenAI 개발 서버

이 서버는 localhost 개발 검증용입니다. GitHub Pages는 Python 서버를 실행하지 않습니다. 공개 서비스 연결에는 별도 호스팅·HTTPS·사용자 인증·지속형 사용량 제한이 필요합니다. 로그인 없는 유료 API 프록시를 공개하지 않도록 현재 서버는 127.0.0.1만 사용합니다.

## 환경 변수

- `LLM_API_KEY`: OpenAI API 키. Codex 환경 설정의 보안 항목에 등록합니다. 이 환경에서는 OPENAI_API_KEY가 예약 이름이라 LLM_API_KEY를 사용합니다. 다른 개발 PC에서는 OPENAI_API_KEY도 읽습니다.
- `EVAL_MODEL`: 기본 gpt-4.1-mini. 초기 검증용으로 선택했으며 최신/최적 모델이라고 주장하지 않습니다. 계정에서 해당 모델 접근이 가능해야 합니다.
- `EMBED_MODEL`: 기본 text-embedding-3-small.

키를 소스 코드, 브라우저 저장소, GitHub 또는 채팅에 넣지 마세요. ChatGPT 구독과 별도의 OpenAI API 결제/사용 한도가 필요합니다. 개발 서버도 실제 호출하면 과금됩니다. 시간당 평가 요청 10회·동시 1회 제한은 프로세스 단위의 개발용 제한이며 재시작하면 초기화됩니다. OpenAI 프로젝트에서 사용량 알림/제한을 별도로 설정하세요.

## 실행 (Python 3.10+, 추가 설치 없음)

저장소 루트에서:

```sh
python3 -m backend.server --port 8000
```

서버와 같은 컴퓨터의 브라우저에서 포트 8000을 열어 후보 화면의 AI 평가를 사용합니다. 기존 npm start(3000)는 정적 웹앱이고 AI를 실행하지 않습니다. API 준비 상태는 GET /api/health, 평가는 POST /api/evaluate입니다. 키의 존재만 health에 표시하며 키 유효성은 실제 호출로 확인해야 합니다.

## 의미 검색 색인

기본은 서버의 제목 글자 조각 검색입니다. 아래 명령은 학생/확인필요 작품 제목을 OpenAI 임베딩 API로 전송하고 **유료 호출**로 색인을 만듭니다. 지도논문은 제외합니다.

```sh
python3 -m backend.server --build-index
```

색인 생성 후 서버를 재시작하세요. 데이터/모델이 일치하는 완성된 색인만 사용합니다. 배치별로 저장하므로 중단 후 재실행 시 이어서 만듭니다. 의미 검색도 전체 보고서의 중복 검사는 아닙니다.

## 평가와 저장

- 이름은 전송하지 않습니다. 아이디어·학년·예산·기간·사용자가 적은 장비/관심사를 보냅니다.
- 아이디어마다 최대 5개 제목 자료를 참고합니다. 생성·실험 설계 도구는 아직 구현하지 않았습니다.
- OpenAI Responses API와 strict JSON schema를 사용합니다. 점수 범위, 아이디어 개수/번호, 출처 ID를 서버에서 다시 검증합니다.
- 수상 확률이 아니라 임시 탐구 기준 적합도입니다. 공식 대회 심사 기준은 아직 입력하지 않았습니다.
- 평균/PASS/상위3 선정은 서버 코드로 계산합니다. PASS는 평균이 기준값보다 큰 경우입니다.
- 평가 결과는 .local/evaluations.sqlite3에 저장하고 동일 입력/모델/루브릭/데이터/검색방식 요청은 24시간 재사용합니다.
- .local은 Git에서 제외하며 서버의 공개 파일 목록에도 없습니다. 이 개발 서버에는 계정별 데이터 분리와 평가 목록 API가 없습니다.
- Responses의 store는 false입니다. 이는 제공자의 모든 데이터 보존 정책을 비활성화한다는 뜻은 아닙니다.
- AI는 입력·검색 자료를 명령으로 따르지 않도록 지시하며 근거 없는 출처는 저장하지 않습니다. 평가 정확성은 선생님의 실제 사례 검증이 필요합니다.

## 검증 및 다음 단계

```sh
python3 -m unittest discover -s backend/tests -v
npm test
```

API 키가 없으면 실제 OpenAI 호출과 색인 생성은 검증할 수 없습니다. 가짜 API 응답을 사용한 계약/오류 처리 테스트와 실제 유료 AI 호출을 구분합니다. 키 등록 → 소량 실제 평가 → 비용·근거 검토 → 의미 검색 색인 → 인증이 있는 공개 서버 배포 순으로 진행합니다. GitHub Pages 설정만으로 AI 서버가 공개되지는 않습니다.

## 최근 실제 호출 확인 (2026-11-16)

시크릿이 현재 환경에 전달되는 것까지 확인했습니다. 실제 Responses API 평가 요청은 HTTP 429 / insufficient_quota로 거절됐습니다. 키 재등록 대신 OpenAI API 결제·크레딧·사용 한도를 확인해야 합니다. 이후 상태가 바뀌면 소량 평가를 다시 검증합니다. 코드에서 결제/잔액 부족과 일시적 요청 제한 메시지를 구분합니다.

## 크레딧 충전 후 실제 검증 (2026-11-16)

이전 insufficient_quota 이후 크레딧 충전으로 실제 평가가 성공했습니다. 제목 표현 검색·의미 검색 각각 1건의 평가와 SQLite 저장/24시간 캐시 경로를 확인했습니다. 지도논문을 제외한 제목 2,190건의 임베딩 색인을 .local에 생성했습니다. 새 서버는 완성된 색인을 읽어 semantic 모드를 사용합니다. 실제 서버의 캐시 결과를 브라우저에 표시하는 검사도 통과했습니다. 공개 API 서버는 아직 배포하지 않았으며 단일 사례로 평가 정확성을 확정할 수 없습니다.
